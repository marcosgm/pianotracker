# API Contracts

This directory contains API contract specifications for the Piano Practice Session Tracker feature.

## Files

- **openapi.yaml**: Complete OpenAPI 3.0.3 specification for the REST API
  - Authentication endpoints (register, login, logout, refresh, me)
  - Session endpoints (create, read, update, delete, list, stats)
  - Request/response schemas with validation rules
  - Error responses and status codes

## Usage

### View API Documentation

1. **Swagger UI** (auto-generated by FastAPI):
   ```
   http://localhost:8000/docs
   ```

2. **ReDoc** (alternative documentation):
   ```
   http://localhost:8000/redoc
   ```

3. **Local Swagger Editor**:
   ```bash
   docker run -p 8080:8080 -e SWAGGER_FILE=/openapi.yaml \
     -v $(pwd)/contracts:/contracts swaggerapi/swagger-editor
   ```
   Then open http://localhost:8080

### Generate Client SDK

Using OpenAPI Generator:

```bash
# TypeScript/Fetch client for frontend
openapi-generator-cli generate \
  -i contracts/openapi.yaml \
  -g typescript-fetch \
  -o frontend/src/generated-api

# Python client for testing
openapi-generator-cli generate \
  -i contracts/openapi.yaml \
  -g python \
  -o backend/tests/generated-client
```

## Key API Endpoints

### Authentication
- `POST /api/auth/register` - Create new user
- `POST /api/auth/login` - Authenticate user (get JWT)
- `POST /api/auth/logout` - Invalidate session
- `POST /api/auth/refresh` - Refresh access token
- `GET /api/auth/me` - Get current user profile

### Practice Sessions
- `POST /api/sessions` - Create new session
- `GET /api/sessions` - List sessions (paginated, filterable)
- `GET /api/sessions/{id}` - Get single session
- `PUT /api/sessions/{id}` - Update session notes
- `DELETE /api/sessions/{id}` - Delete session
- `GET /api/sessions/stats` - Get practice statistics

## Authentication Flow

1. **Register**: `POST /api/auth/register` → Returns access token + sets refresh token cookie
2. **Login**: `POST /api/auth/login` → Returns access token + sets refresh token cookie
3. **Protected Requests**: Include `Authorization: Bearer <access_token>` header
4. **Token Expired (401)**: `POST /api/auth/refresh` → Get new access token
5. **Logout**: `POST /api/auth/logout` → Clears refresh token cookie

## Validation Rules

### Session Creation Constraints
- `practice_type` must be one of: `chords`, `scales`, `course`, `songs`
- `tempo` is **required** (90-120) for `chords` and `scales`
- `tempo` must be **null** for `course` and `songs`
- `tempo` must be an **integer** (no decimals)
- `notes` are optional (max 500 characters)
- `date` is automatically set to current date (no user input)

### Password Requirements
- Minimum 8 characters
- Must contain at least one digit
- Must contain at least one letter
- Hashed with bcrypt (cost 12) before storage

## Rate Limits

- **Auth endpoints** (`/api/auth/*`): 5 requests/minute per IP
- **Session endpoints** (`/api/sessions/*`): 100 requests/minute per user
- **Statistics endpoint** (`/api/sessions/stats`): 10 requests/minute per user

## Error Codes

| Code | Meaning | Common Causes |
|------|---------|---------------|
| 400 | Bad Request | Invalid input format, missing required fields |
| 401 | Unauthorized | Missing or expired token, invalid credentials |
| 403 | Forbidden | Attempting to access another user's session |
| 404 | Not Found | Session or user does not exist |
| 409 | Conflict | Email already registered |
| 422 | Unprocessable Entity | Validation error (detailed in response body) |
| 429 | Too Many Requests | Rate limit exceeded |
| 500 | Internal Server Error | Unexpected server error |
